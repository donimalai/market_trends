# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Context

Local Python pipeline + Streamlit dashboard answering one question for non-technical bank management: "how has ASX 200 market activity trended over the past 90 days, and is there anything we should be watching?" — using RBA cash rate as the macro overlay. Everything runs locally against a single DuckDB file; there is no cloud dependency.

## Commands

```
# setup
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# run the full pipeline (ingestion -> align -> metrics)
python run_pipeline.py

# run the dashboard
streamlit run src/dashboard/app.py

# run one extractor standalone
python src/ingestion/rba_extractor.py
python src/ingestion/yahoo_extractor.py

# demo the failure-handling path
python scripts/simulate_failure.py

# tests
pytest
pytest tests/test_metrics.py
pytest tests/test_metrics.py::test_rolling_avg_volume_placeholder   # single test
```

There is no linter/formatter configured yet — none of ruff/black/flake8 are set up in this repo.

## Architecture

- **Layering:** `data/raw/` (immutable Parquet, gitignored) → `dq_log` table → `src/transform/align.py` → `src/transform/metrics.py` → `src/dashboard/app.py`. All curated tables and the DQ log live in one file, `data/warehouse.duckdb` (gitignored, regenerated by the pipeline — never commit it).
- **Tables:** `dq_log` (one row per run, success/warning/failure — no exceptions), `curated.aligned_daily` (joined + timezone-normalized), `curated.metrics_daily` (final metrics + `rag_signal`). The dashboard reads **only** from `curated.metrics_daily`.
- **Import direction is one-way:** `src/ingestion/rba_extractor.py` and `yahoo_extractor.py` import `dq_logger.py`; `dq_logger.py` must never import extractor code. This avoids circular imports — keep new sources following the same direction.
- **Timezone handling lives in `align.py` only.** RBA cash rate changes are published as of an AEST effective date; yfinance ASX200 timestamps need explicit conversion to AEST calendar dates before the join, or the two series misalign by a day. Don't re-derive this conversion elsewhere.
- **Forward-fill is deliberate:** RBA cash rate doesn't change daily, so `align.py` forward-fills it onto every ASX200 trading day, then left-joins on `date`, keeping only ASX200 trading days in the final table.
- **`src/transform/metrics.py` must implement exactly what's specified in `docs/metric_definitions.md`.** That file is authored by the human lead and reviewed *before* any agent implements `metrics.py` — the code must not redefine or reinterpret a metric on its own. If `docs/metric_definitions.md` is still the placeholder text, treat that as a signal to stop and ask rather than inventing definitions.
- **No silent failures:** every extraction run, success or failure, writes exactly one row to `dq_log` via `dq_logger.log_run(...)`.
